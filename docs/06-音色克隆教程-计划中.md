# 音色克隆教程（状态：计划中）

> **这一页现在不是教程。**
> 它只有一份大纲和已经验证过的技术事实，**没有可直接照做的安装步骤**。
> 补齐步骤需要在本机重新跑一遍完整流程、记录版本号与耗时，那件事还没做。
> 在"状态"改成"已发布"之前，请不要把下面任何内容当作操作指南。

---

## 一、这条要做什么

把创作者本人的声音做成一个可复用的 TTS 音色，用来给短片配旁白与对白。

**目标不是"像主播"，是"像这个人自己在低声说话"。**

## 二、为什么它是"计划中"

有三个原因，任何一条不解决都不能发布成教程：

1. **效果没达标**。技术链路是通的（10 句台词全部生成、时长与静音都通过检查），
   但音色自然度不满意——拖尾、气口偏平、句尾下沉不够。最后**没有用于发布版本**。
   一个"能跑但效果不好"的教程，等于教别人踩同一个坑还不告诉他出口在哪。
2. **步骤没有重新走过**。当时是在调试中一步步试出来的，中间有试错和临时改动。
   直接把它写成"标准流程"，会把那些临时改动当成必要步骤教出去。
3. **硬件门槛要如实写**。这套必须用 NVIDIA 显卡跑，显存要求不低。
   不写清楚硬件基线，会让没有独显的人白花几个小时。

## 三、已经验证过的事实

以下都是**在这个项目里真实发生过的**，可以直接引用：

| 项 | 已验证的值 |
|---|---|
| 方案 | GPT-SoVITS v2 本地部署 + 小样本微调（不是零样本克隆） |
| Python 环境 | 独立 venv，Python 3.10.11 |
| 深度学习框架 | torch 2.5.1 + cu121，CUDA 可用为 True |
| 显卡 | NVIDIA RTX 4060 Laptop，实显存 **8188 MiB**（需用 `nvidia-smi` 取真值，不能用 WMI 的 `AdapterRAM`，它因 uint32 截断会报成 4GB） |
| 参考音 | 一条 4.40 秒、32kHz 单声道录音，配一段固定文本 |
| 训练规模 | 极短素材（1–2 分钟）微调 |
| 产物 | SoVITS 权重 `.pth` + GPT 权重 `.ckpt`，数十 MB 级 |
| 可用性 | 10 句台词全部生成成功，逐句通过时长上限与"无 1 秒以上静音"检查 |
| 结论 | 链路可用，**音色自然度未达标**，未用于发布 |

**踩过的三个坑（已验证）：**

1. **输出被截成零点几秒** —— 参考音采样率/声道格式与权重期望不一致。
2. **参考音被拒** —— 参考音必须配"它实际说的那段文本"，而且参考音与文本要成对复用，
   不能拿 A 的音频配 B 的文本。
3. **权重加载报错** —— 推理权重必须是训练导出的那一对（`.pth` 给 SoVITS、`.ckpt` 给 GPT），
   两者不能混用不同 epoch。

这三点是这套方案里最容易卡住人的地方，也是这份大纲里唯一确定能写进教程的部分。

## 四、教程补齐时要做的事

按顺序，一项没做完就不发布：

1. **重跑一遍干净安装**：从空 venv 开始，记录每一步的版本号、下载体积、安装耗时。
2. **记录硬件基线**：显存占用峰值、单句生成耗时、全片 10 句总耗时。
3. **给出素材要求**：录音时长下限、采样率、必须单声道、必须安静环境、
   必须配固定文本——每一条都要有"不满足会怎样"的后果说明。
4. **给出训练参数**：epoch 数量与选择依据（哪个 epoch 开始过拟合，怎么看出来的）。
5. **放出对比样例**：同一句台词的原始录音 vs 克隆输出，让读者自己判断差距。
6. **写清失败模式**：拖尾、气口平、句尾下沉不够分别怎么调，调不动就承认调不动。

## 五、会公开什么，不会公开什么

| 内容 | 是否公开 |
|---|---|
| 流程步骤、参数、版本号 | ✅ 会 |
| 硬件要求与耗时 | ✅ 会 |
| 例句对比音频（**用合成音或公开文本**） | ✅ 会（仅在不涉及个人音色特征的前提下） |
| 创作者的原始录音 | ❌ 不公开 |
| 创作者本人的音色模型权重（`.pth` / `.ckpt`） | ❌ 不公开 |
| 用来训练的真实语音数据集 | ❌ 不公开 |

原因很简单：音色模型等于生物特征。一个能模仿你说话的文件，不该被公开分发。
教程要教的是**方法**，不是把某个人的声音复制品送出去。
